# Piper TTS Service

Internal HTTP service that provides text-to-speech synthesis for fs-enrs.
Uses the [Piper TTS engine](https://github.com/rhasspy/piper) (piper-tts Python package).

## Architecture

Two integration paths call this service:

**ENS campaign pre-synthesis** (Node.js → Piper):
```
ENS trigger (phone/IVR)
   ↓
backend: ensInternalController.js → piperClient.js
   ↓
POST http://<PIPER_URL>/synthesize
   ↓
Piper TTS service  (this service)
   ↓
piper-tts (ONNX inference) → sox resample → WAV @ 8000 Hz
   ↓
WAV file written to recordings_dir; path passed to FreeSWITCH campaign engine
```

**IVR TTS nodes** (FreeSWITCH Lua → Piper directly):
```
FreeSWITCH call → ivr_executor.lua (generated by deploymentEngine.js)
   ↓
curl -m 25 POST http://<PIPER_URL>/synthesize
   ↓
WAV file written to recordings_dir/ivr_tts/; FreeSWITCH plays it back
```

Port by deployment method:
- **Docker**: `http://piper:5000` (Docker network hostname, set by docker-compose)
- **Source/DEV**: `http://127.0.0.1:5002` (set `PIPER_BACKEND_URL` and `PIPER_LUA_URL` in backend `.env.dev`)

The React browser never calls this service directly.

## API

| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Liveness probe — 200 if process is running |
| `GET` | `/ready` | Readiness probe — 200 only if voice model(s) loaded |
| `GET` | `/voices` | List available voice models |
| `POST` | `/synthesize` | Synthesize text to WAV audio |

### POST /synthesize

**Request body (JSON):**

```json
{
  "text":        "Hello, this is a test.",
  "voice":       "en_US-lessac-medium",
  "sample_rate": 8000,
  "channels":    1
}
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `text` | string | (required) | 1–5000 chars; alphanumeric + punctuation |
| `voice` | string | `en_US-lessac-medium` | Must be a registered, enabled voice |
| `sample_rate` | int | `8000` | Allowed: 8000, 16000, 22050, 44100, 48000 |
| `channels` | int | `1` | 1 (mono) or 2 (stereo) |

**Response:** `audio/wav` bytes with response headers:

| Header | Example | Notes |
|---|---|---|
| `X-Audio-Duration-Sec` | `2.340` | Duration of the generated audio |
| `X-Audio-Sample-Rate` | `8000` | Actual output sample rate |
| `X-Audio-Channels` | `1` | Actual output channels |
| `X-Voice` | `en_US-lessac-medium` | Voice used for synthesis |
| `X-Synthesis-Latency-Ms` | `1234.5` | Total latency including resampling |

## Configuration

Set via environment variables:

| Variable | Default | Description |
|---|---|---|
| `PIPER_MODEL_DIR` | `/app/models` | Directory containing ONNX model files |
| `PIPER_DEFAULT_VOICE` | `en_US-lessac-medium` | Default voice if not specified in request |
| `PIPER_SAMPLE_RATE` | `8000` | Default output sample rate |
| `PIPER_MAX_CONCURRENT` | `2` | Max simultaneous synthesis requests |
| `PIPER_SYNTHESIS_TIMEOUT_SEC` | `30` | Per-request timeout |
| `PIPER_MAX_TEXT_LENGTH` | `5000` | Max input text characters |
| `LOG_LEVEL` | `INFO` | Logging level (DEBUG/INFO/WARNING/ERROR) |

## Running from Source (Development)

### System prerequisites

```bash
# Debian/Ubuntu
sudo apt-get install -y python3.11 python3.11-venv sox libsox-fmt-all libsndfile1

# Verify sox is on PATH
sox --version
```

### One-time environment setup

```bash
cd services/piper
python3.11 -m venv .venv
# Install production + development/test dependencies:
.venv/bin/pip install -r requirements-dev.txt
```

> `requirements.txt` — production dependencies only (fastapi, uvicorn, piper-tts).  
> `requirements-dev.txt` — extends requirements.txt with pytest, httpx for local testing.  
> The Docker image installs only `requirements.txt`.

### Model files

Download model files and place them in a directory accessible to the service.
See `models/README.md` for the approved voice, download URL, and checksum verification.

On the dev server the models live at `/opt/freeswitch-ui/enrs-tools/voices/`.

### Starting Piper

```bash
cd services/piper
PIPER_MODEL_DIR=/path/to/voices ./start-dev.sh
```

`start-dev.sh` exports defaults (`PIPER_HOST=127.0.0.1`, `PIPER_PORT=5002`) and
launches uvicorn. Override any variable before calling the script or via `.env.dev`
(copy from `.env.example`).

### Verify

```bash
curl http://127.0.0.1:5002/health     # → {"status":"ok"}
curl http://127.0.0.1:5002/ready      # → 200 with voices once model is loaded
curl -s -X POST http://127.0.0.1:5002/synthesize \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello from Piper.","sample_rate":8000}' \
  -o /tmp/test.wav
file /tmp/test.wav   # RIFF (little-endian) data, WAVE audio, Microsoft PCM, 16 bit, mono 8000 Hz
```

### Cold-start latency

The first synthesis request after startup loads the ONNX model into memory (12–16 s for
`en_US-lessac-medium`). Subsequent requests are fast (< 1 s for short phrases). The Lua
`curl -m 25` timeout is sized to survive this cold start. Do not alarm at the first-request
latency on a freshly started instance.

### ENRS backend integration

Set `PIPER_BACKEND_URL=http://127.0.0.1:5002` and `PIPER_LUA_URL=http://127.0.0.1:5002` in
`backend/.env.dev`. `deploymentEngine.js` reads `PIPER_LUA_URL` (via `config.piper.luaUrl`)
and embeds it into `ivr_executor.lua` at deploy time.

### Running tests from source

Install `requirements-dev.txt` first (see setup above).

```bash
cd services/piper

# Unit tests — no model required (fast, always runnable)
.venv/bin/pytest tests/ -m "not requires_model" -v

# Full test suite — model + sox required
PIPER_MODEL_DIR=/path/to/voices .venv/bin/pytest tests/ -v
```

Expected result on a server with model + sox: 40 passed, 2 skipped, 0 failed.

## Running in Docker (standalone test)

```bash
# From repo root
docker build -t fs-enrs-piper:latest services/piper/

docker run --rm -p 5000:5000 \
  -v /opt/freeswitch-ui/enrs-tools/voices:/app/models:ro \
  -e PIPER_SAMPLE_RATE=8000 \
  fs-enrs-piper:latest

# Test
curl http://localhost:5000/health
curl http://localhost:5000/ready
curl http://localhost:5000/voices

curl -s -X POST http://localhost:5000/synthesize \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello from Piper.","sample_rate":8000}' \
  -o /tmp/test.wav

# Verify WAV format
soxi /tmp/test.wav 2>/dev/null || file /tmp/test.wav
```

## Security

- This service is an **internal-only** Docker service — never expose port 5000 externally.
- All input is validated against strict allowlists.
- No shell=True subprocess calls (sox is invoked via exec array).
- Voice names are validated against `[A-Za-z0-9_\-\.]+` pattern only.
- Arbitrary file paths from callers are rejected.
